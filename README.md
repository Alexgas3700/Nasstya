# n8n Workflow для публикации контента в VK

Этот проект содержит готовый n8n workflow для автоматической публикации контента в социальной сети ВКонтакте (VK) с использованием VK API.

## 📋 Описание

Workflow обеспечивает:
- ✅ Автоматическую публикацию постов в VK по расписанию
- ✅ Аутентификацию через VK API с использованием access token
- ✅ Подготовку и валидацию данных перед публикацией
- ✅ Логирование успешных публикаций и ошибок
- ✅ Проверку статуса опубликованных постов
- ✅ Обработку ошибок VK API

## 🚀 Быстрый старт

### Предварительные требования

1. **n8n** - установленный и запущенный экземпляр n8n
   - Версия: 1.0.0 или выше
   - Можно использовать: Docker, npm, или n8n Cloud

2. **VK API Access Token** - токен доступа к VK API
   - Необходимые права: `wall`, `offline`
   - Получить можно через VK Dev Portal

### Установка n8n

#### Вариант 1: Docker (рекомендуется)

```bash
docker run -it --rm \
  --name n8n \
  -p 5678:5678 \
  -v ~/.n8n:/home/node/.n8n \
  n8nio/n8n
```

#### Вариант 2: npm

```bash
npm install n8n -g
n8n start
```

#### Вариант 3: n8n Cloud

Зарегистрируйтесь на [n8n.cloud](https://n8n.cloud) и создайте новый workspace.

## 🔧 Настройка VK API

### Шаг 1: Создание VK приложения

1. Перейдите на [VK Dev Portal](https://dev.vk.com/)
2. Нажмите "Создать приложение"
3. Выберите тип "Standalone приложение"
4. Заполните название и описание
5. После создания скопируйте **App ID** и **Secure Key**

### Шаг 2: Получение Access Token

#### Метод 1: Через Implicit Flow (для тестирования)

Откройте в браузере URL (замените `YOUR_APP_ID` на ваш App ID):

```
https://oauth.vk.com/authorize?client_id=YOUR_APP_ID&display=page&redirect_uri=https://oauth.vk.com/blank.html&scope=wall,offline&response_type=token&v=5.131
```

После авторизации скопируйте `access_token` из URL.

#### Метод 2: Через Service Token (для production)

1. В настройках приложения перейдите в раздел "Настройки"
2. Создайте сервисный ключ доступа
3. Выберите необходимые права: `wall`, `offline`
4. Скопируйте полученный токен

### Шаг 3: Определение Owner ID

Owner ID - это ID группы или пользователя, от имени которого будут публиковаться посты.

**Для группы:**
- Откройте страницу группы
- ID группы указан в URL: `vk.com/club123456` → owner_id = `-123456` (с минусом!)
- Или используйте метод API: `https://api.vk.com/method/groups.getById?group_id=YOUR_GROUP_SCREEN_NAME&v=5.131`

**Для личной страницы:**
- Ваш ID указан в URL профиля: `vk.com/id123456` → owner_id = `123456`

## 📥 Импорт Workflow в n8n

### Шаг 1: Открыть n8n

Откройте n8n в браузере (по умолчанию: `http://localhost:5678`)

### Шаг 2: Импортировать workflow

1. Нажмите на кнопку "**+**" в верхнем правом углу
2. Выберите "**Import from File**"
3. Загрузите файл `n8n_workflow.json` из этого репозитория
4. Workflow будет импортирован и откроется в редакторе

### Шаг 3: Настроить Credentials

1. Откройте любой узел, использующий VK API (например, "VK API: Publish Post")
2. В поле "Authentication" выберите "Generic Credential Type"
3. Создайте новый credential:
   - **Name**: VK API Token
   - **Credential Type**: Generic Credential Type
   - Добавьте параметр:
     - **Name**: `vkAccessToken`
     - **Value**: Ваш VK Access Token
4. Сохраните credential

### Шаг 4: Настроить параметры публикации

В узле "**Prepare Post Data**" настройте параметры по умолчанию:

```javascript
const contentData = {
  message: 'Ваш текст поста',
  attachments: '', // Ссылки на фото, видео и т.д.
  owner_id: '-123456', // ID группы (с минусом) или пользователя
  from_group: 1 // 1 = от имени группы, 0 = от имени пользователя
};
```

### Шаг 5: Настроить расписание

В узле "**Schedule: Daily Content Publishing**":

1. Откройте настройки узла
2. Выберите интервал публикации:
   - **Hourly** - каждый час
   - **Daily** - ежедневно в указанное время
   - **Weekly** - еженедельно
   - **Monthly** - ежемесячно
3. Укажите точное время запуска (если применимо)

## 🎯 Использование Workflow

### Ручной запуск

1. Откройте workflow в редакторе n8n
2. Нажмите кнопку "**Execute Workflow**" в правом верхнем углу
3. Проверьте результаты выполнения в каждом узле

### Автоматический запуск по расписанию

1. Активируйте workflow, переключив тумблер "**Active**" в верхнем правом углу
2. Workflow будет автоматически запускаться по настроенному расписанию
3. Проверяйте логи выполнения в разделе "**Executions**"

### Тестирование

Перед активацией рекомендуется протестировать workflow:

1. Нажмите на узел "**Schedule: Daily Content Publishing**"
2. Нажмите "**Execute Node**"
3. Проверьте, что данные корректно передаются через все узлы
4. Убедитесь, что пост появился в VK

## 📊 Структура Workflow

### Узлы (Nodes)

1. **Schedule: Daily Content Publishing** (Cron Trigger)
   - Запускает workflow по расписанию
   - Настраивается интервал выполнения

2. **Prepare Post Data** (Function)
   - Подготавливает данные для публикации
   - Валидирует обязательные поля
   - Формирует структуру запроса к VK API

3. **VK API: Publish Post** (HTTP Request)
   - Отправляет POST запрос к VK API
   - Метод: `wall.post`
   - Публикует контент на стене

4. **Validate Response** (Function)
   - Проверяет ответ VK API на ошибки
   - Извлекает ID опубликованного поста
   - Генерирует исключение при ошибке

5. **Check Success** (IF)
   - Разделяет поток на успешные и неуспешные публикации

6. **VK API: Verify Post** (HTTP Request)
   - Опционально: проверяет, что пост действительно опубликован
   - Метод: `wall.get`

7. **Log Success** (Function)
   - Логирует успешные публикации
   - Сохраняет ID поста и timestamp

8. **Log Error** (Function)
   - Логирует ошибки публикации
   - Сохраняет детали ошибки для анализа

9. **Merge Logs** (Merge)
   - Объединяет логи успешных и неуспешных публикаций

## 🔍 Параметры публикации

### Обязательные параметры

- `owner_id` - ID группы (с минусом) или пользователя
- `message` - текст поста
- `access_token` - токен доступа VK API

### Опциональные параметры

- `attachments` - вложения (фото, видео, ссылки)
  - Формат: `photo-123456_789,video-123456_456`
- `from_group` - публиковать от имени группы (1) или пользователя (0)
- `lat`, `long` - координаты для геометки
- `services` - экспорт в другие соцсети
- `signed` - добавить подпись автора (для групп)
- `publish_date` - отложенная публикация (Unix timestamp)

### Пример данных для публикации

```json
{
  "message": "Привет! Это автоматический пост из n8n 🚀",
  "owner_id": "-123456789",
  "from_group": 1,
  "attachments": "photo-123456_789012345",
  "lat": 55.7558,
  "long": 37.6173
}
```

## 📝 Логирование

Workflow автоматически логирует:

### Успешные публикации

```json
{
  "status": "SUCCESS",
  "post_id": 123456,
  "timestamp": "2026-01-22T10:30:00.000Z",
  "message": "Post published successfully",
  "workflow_execution_id": "abc123"
}
```

### Ошибки

```json
{
  "status": "ERROR",
  "error_message": "VK API Error: Access denied (Code: 15)",
  "timestamp": "2026-01-22T10:30:00.000Z",
  "workflow_execution_id": "abc123",
  "input_data": {...}
}
```

Логи доступны:
- В консоли n8n (для Function узлов)
- В разделе "Executions" n8n UI
- Можно настроить отправку в внешние системы логирования

## 🛠 Расширенная настройка

### Добавление изображений

1. Загрузите изображение через VK API метод `photos.getWallUploadServer`
2. Получите ID загруженного фото
3. Добавьте ID в параметр `attachments`

Пример узла для загрузки фото можно добавить перед "Prepare Post Data".

### Интеграция с внешними источниками

Можно заменить Cron Trigger на:
- **Webhook** - для получения данных от внешних систем
- **RSS Feed** - для автоматической публикации из RSS
- **Google Sheets** - для публикации из таблиц
- **Airtable** - для публикации из базы данных

### Множественные публикации

Для публикации в несколько групп:
1. Добавьте узел "Split In Batches" после "Prepare Post Data"
2. Передайте массив `owner_id` разных групп
3. Workflow будет публиковать в каждую группу по очереди

### Модерация контента

Добавьте узел "IF" после "Prepare Post Data" для проверки:
- Длины текста
- Наличия запрещенных слов
- Валидности ссылок

## ❗ Troubleshooting

### Ошибка: "Invalid access token"

**Решение:**
- Проверьте, что токен скопирован полностью
- Убедитесь, что токен не истек
- Проверьте права доступа токена (должны быть `wall`, `offline`)

### Ошибка: "Access denied"

**Решение:**
- Проверьте, что у токена есть права на публикацию в указанной группе
- Убедитесь, что вы являетесь администратором группы
- Для групп: owner_id должен быть с минусом (например, `-123456`)

### Ошибка: "Too many requests per second"

**Решение:**
- VK API имеет лимит: 3 запроса в секунду
- Добавьте задержку между запросами (узел "Wait")
- Используйте метод `execute` для батчинга запросов

### Workflow не запускается по расписанию

**Решение:**
- Убедитесь, что workflow активирован (тумблер "Active")
- Проверьте настройки Cron узла
- Проверьте логи n8n на наличие ошибок

### Пост публикуется, но не отображается

**Решение:**
- Проверьте настройки приватности группы
- Убедитесь, что пост не попал в модерацию
- Проверьте параметр `from_group` (должен быть 1 для групп)

## 🔐 Безопасность

### Рекомендации

1. **Не храните токены в коде** - используйте n8n Credentials
2. **Используйте сервисные токены** для production
3. **Ограничьте права токена** - только необходимые scope
4. **Регулярно обновляйте токены** - используйте `offline` scope для долгосрочных токенов
5. **Не публикуйте токены в Git** - добавьте в `.gitignore`

### Ротация токенов

Для автоматической ротации токенов:
1. Используйте OAuth 2.0 flow
2. Храните refresh_token в n8n Credentials
3. Добавьте узел для обновления access_token перед публикацией
