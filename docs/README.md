# Интеграция N8N для Email-рассылок

## 📋 Описание проекта

Это комплексное решение для автоматизации email-рассылок на базе платформы n8n. Система позволяет создавать персонализированные email-кампании, отслеживать статус доставки и анализировать результаты рассылок.

## 🎯 Основные возможности

- ✅ **Импорт получателей из CSV** - загрузка списков email-адресов с персональными данными
- ✅ **Персонализация писем** - использование шаблонов с подстановкой имен и других данных
- ✅ **Тестовый режим** - отправка тестовых писем перед запуском полной кампании
- ✅ **Отслеживание статуса** - мониторинг доставки, ошибок и статистики
- ✅ **Планирование рассылок** - автоматический запуск по расписанию
- ✅ **Webhook-интеграция** - запуск рассылок через API
- ✅ **Статистика кампаний** - агрегация данных о результатах рассылки

## 🚀 Быстрый старт

### Предварительные требования

1. **n8n установлен и запущен**
   ```bash
   # Установка n8n через npm
   npm install n8n -g
   
   # Или через Docker
   docker run -it --rm \
     --name n8n \
     -p 5678:5678 \
     -v ~/.n8n:/home/node/.n8n \
     n8nio/n8n
   ```

2. **Настроены учетные данные для отправки email**
   - SMTP сервер (Gmail, SendGrid, Mailgun и т.д.)
   - Или API ключи для email-сервисов

3. **База данных для логирования** (опционально)
   - PostgreSQL, MySQL, MongoDB или другая

### Шаг 1: Импорт workflow в n8n

1. Откройте n8n в браузере (обычно `http://localhost:5678`)
2. Перейдите в раздел "Workflows"
3. Нажмите "Import from File"
4. Выберите файл `workflows/email_campaign_workflow.json`
5. Workflow будет импортирован со всеми нодами

### Шаг 2: Настройка учетных данных

#### Настройка SMTP

1. В n8n перейдите в "Credentials" → "New"
2. Выберите "SMTP"
3. Заполните данные:
   ```
   Host: smtp.gmail.com (для Gmail)
   Port: 587
   Secure: false (для TLS)
   User: ваш_email@gmail.com
   Password: ваш_пароль_приложения
   ```

#### Настройка базы данных (опционально)

1. В n8n перейдите в "Credentials" → "New"
2. Выберите "PostgreSQL" (или другую БД)
3. Заполните данные подключения:
   ```
   Host: localhost
   Database: n8n_campaigns
   User: postgres
   Password: ваш_пароль
   Port: 5432
   ```

4. Создайте таблицу для логов:
   ```sql
   CREATE TABLE email_campaign_log (
       id SERIAL PRIMARY KEY,
       email VARCHAR(255),
       status VARCHAR(50),
       sent_at TIMESTAMP,
       campaign_id VARCHAR(100),
       subject TEXT,
       error TEXT,
       created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
   );
   ```

### Шаг 3: Настройка workflow

1. Откройте импортированный workflow
2. Настройте ноду "Send Email (SMTP)":
   - Выберите созданные SMTP credentials
   - Укажите email отправителя в поле `fromEmail`

3. Настройте ноду "Save to Database" (если используете):
   - Выберите credentials базы данных
   - Проверьте название таблицы

4. Настройте ноду "Load Email Template":
   - Укажите путь к вашему шаблону
   - Или настройте HTTP Request для загрузки из внешнего источника

### Шаг 4: Подготовка данных

#### Формат CSV-файла

Создайте CSV-файл со списком получателей:

```csv
email,first_name,last_name
john.doe@example.com,John,Doe
jane.smith@example.com,Jane,Smith
```

**Обязательные поля:**
- `email` - email-адрес получателя

**Опциональные поля:**
- `first_name` - имя получателя
- `last_name` - фамилия получателя
- Любые другие поля для персонализации

#### Использование шаблонов

В шаблонах можно использовать переменные:
- `{{firstName}}` - имя получателя
- `{{lastName}}` - фамилия получателя
- `{{fullName}}` - полное имя
- `{{email}}` - email-адрес

**Пример:**
```html
<p>Здравствуйте, {{firstName}}!</p>
<p>Ваш email: {{email}}</p>
```

## 📧 Использование системы

### Запуск рассылки вручную

1. Откройте workflow в n8n
2. Нажмите "Execute Workflow"
3. Загрузите CSV-файл с получателями
4. Укажите параметры:
   - `emailTemplate` - текст или HTML шаблона
   - `emailSubject` - тема письма
   - `senderEmail` - email отправителя
   - `testMode` - `true` для тестового режима
   - `testEmails` - список тестовых email через запятую

### Тестовый режим

Перед запуском полной рассылки рекомендуется протестировать:

1. Установите параметр `testMode: true`
2. Укажите тестовые email в `testEmails`:
   ```json
   {
     "testMode": true,
     "testEmails": "test1@example.com,test2@example.com"
   }
   ```
3. Запустите workflow
4. Проверьте полученные письма
5. После проверки установите `testMode: false` для полной рассылки

### Автоматический запуск по расписанию

Workflow включает ноду "Schedule Trigger":

1. Откройте ноду "Schedule Trigger"
2. Настройте расписание:
   - **Cron Expression**: `0 9 * * *` (каждый день в 9:00)
   - Или используйте визуальный редактор
3. Активируйте workflow (переключатель в правом верхнем углу)

**Примеры cron-выражений:**
- `0 9 * * *` - каждый день в 9:00
- `0 9 * * 1` - каждый понедельник в 9:00
- `0 9 1 * *` - первого числа каждого месяца в 9:00
- `0 */6 * * *` - каждые 6 часов

### Запуск через Webhook

Workflow поддерживает запуск через HTTP API:

1. Активируйте workflow
2. Скопируйте URL webhook из ноды "Webhook Trigger"
3. Отправьте POST-запрос:

```bash
curl -X POST https://your-n8n-instance.com/webhook/email-campaign \
  -H "Content-Type: application/json" \
  -d '{
    "csvData": "email,first_name,last_name\njohn@example.com,John,Doe",
    "emailSubject": "Тема письма",
    "emailTemplate": "Здравствуйте, {{firstName}}!",
    "senderEmail": "noreply@example.com",
    "testMode": false
  }'
```

## 📊 Отслеживание результатов

### Статусы доставки

Система отслеживает следующие статусы:
- **sent** - письмо успешно отправлено
- **error** - ошибка при отправке

### Просмотр логов

Если настроена база данных, все результаты сохраняются в таблице `email_campaign_log`:

```sql
-- Просмотр всех отправленных писем
SELECT * FROM email_campaign_log 
ORDER BY created_at DESC;

-- Статистика по кампании
SELECT 
    campaign_id,
    COUNT(*) as total,
    SUM(CASE WHEN status = 'sent' THEN 1 ELSE 0 END) as sent,
    SUM(CASE WHEN status = 'error' THEN 1 ELSE 0 END) as errors
FROM email_campaign_log
GROUP BY campaign_id;
```

### Webhook со статистикой

После завершения рассылки workflow отправляет статистику на указанный webhook:

```json
{
  "total": 100,
  "sent": 98,
  "errors": 2,
  "campaignId": "workflow-123",
  "completedAt": "2026-01-22T10:30:00Z"
}
```

Настройте URL webhook в ноде "Send Statistics Webhook".

## 🎨 Работа с шаблонами

### HTML-шаблоны

Проект включает готовые HTML-шаблоны:

1. **welcome_template.html** - приветственное письмо
   - Современный дизайн с зеленой цветовой схемой
   - Подходит для onboarding новых пользователей

2. **newsletter_template.html** - новостная рассылка

   - Элементы срочности

   - Для простых уведомлений
   - Совместим со всеми почтовыми клиентами

### Создание собственного шаблона

1. Создайте HTML или текстовый файл в папке `templates/`
2. Используйте переменные в двойных фигурных скобках:
   ```html
   <h1>Привет, {{firstName}}!</h1>
   <p>Ваш email: {{email}}</p>
   ```

3. В workflow укажите содержимое шаблона в ноде "Load Email Template"

### Интеграция с внешней системой шаблонов

Вместо локальных шаблонов можно использовать внешний API:

1. Замените ноду "Load Email Template" на "HTTP Request"
2. Настройте запрос к вашему API:
   ```
   Method: GET
   URL: https://your-api.com/templates/{{templateId}}
   ```

## ⚙️ Расширенные настройки

### Использование SendGrid вместо SMTP

1. Замените ноду "Send Email (SMTP)" на "SendGrid"
2. Настройте API ключ SendGrid в credentials
3. SendGrid предоставляет расширенную аналитику (открытия, клики)

### Использование Mailgun

1. Замените ноду на "Mailgun"
2. Настройте API ключ и домен
3. Mailgun поддерживает валидацию email-адресов

### Добавление задержки между письмами

Чтобы избежать блокировки SMTP-сервером:

1. Добавьте ноду "Wait" после "Send Email"
2. Настройте задержку (например, 1-2 секунды)

### Сегментация получателей

Добавьте ноду "Filter" после "Process Email List":

```javascript
// Фильтр по домену
if ($json.email.endsWith('@gmail.com')) {
  return [{ json: $json }];
}
return [];
```

### Обработка отписок

1. Добавьте ноду "HTTP Request" для проверки списка отписок
2. Фильтруйте получателей перед отправкой:

```javascript
// Проверка в списке отписок
const unsubscribed = await fetch('https://your-api.com/unsubscribed/' + $json.email);
if (!unsubscribed) {
  return [{ json: $json }];
}
return [];
```

## 🔒 Безопасность и соблюдение законов

### GDPR и защита данных

- ✅ Храните только необходимые данные
- ✅ Предоставьте возможность отписки в каждом письме
- ✅ Удаляйте данные по запросу пользователя
- ✅ Шифруйте персональные данные в базе

### CAN-SPAM Act (США)

Каждое письмо должно содержать:
- ✅ Реальный адрес отправителя
- ✅ Ссылку на отписку
- ✅ Физический адрес компании
- ✅ Честную тему письма

### Лимиты отправки

Соблюдайте лимиты вашего email-провайдера:
- **Gmail**: 500 писем/день (бесплатно)
- **SendGrid**: от 100 писем/день (бесплатно)
- **Mailgun**: 5000 писем/месяц (бесплатно)

## 🐛 Решение проблем

### Письма не отправляются

1. **Проверьте SMTP credentials:**
   - Правильный ли host и port?
   - Верные ли логин и пароль?
   - Для Gmail используйте "App Password"

2. **Проверьте логи n8n:**
   ```bash
   # В Docker
   docker logs n8n
   
   # В npm
   ~/.n8n/logs/
   ```

3. **Тестируйте SMTP-подключение:**
   ```bash
   telnet smtp.gmail.com 587
   ```

### Письма попадают в спам

1. **Настройте SPF, DKIM, DMARC** для вашего домена
2. **Используйте проверенный домен** отправителя
3. **Избегайте спам-триггеров** в теме и тексте:
   - Много восклицательных знаков!!!
   - КАПС
   - Слова "бесплатно", "выиграй" и т.д.

4. **Прогрейте IP-адрес** - начните с малых объемов

### Ошибки при импорте CSV

1. **Проверьте кодировку** - используйте UTF-8
2. **Проверьте разделитель** - должна быть запятая
3. **Проверьте заголовки** - первая строка должна содержать названия колонок
4. **Удалите пустые строки**

### База данных не сохраняет логи

1. **Проверьте подключение к БД**
2. **Убедитесь, что таблица создана**
3. **Проверьте права пользователя БД**

## 📈 Оптимизация производительности

### Для больших списков получателей

1. **Используйте батчинг:**
   - Разделите список на группы по 100-500 адресов
   - Добавьте задержку между батчами

2. **Используйте очереди:**
   - Интегрируйте с RabbitMQ или Redis
   - Обрабатывайте письма асинхронно

3. **Масштабируйте n8n:**
   - Используйте несколько инстансов n8n
   - Настройте load balancer

### Кэширование шаблонов

Если шаблоны загружаются из внешнего API:

1. Добавьте ноду "Redis" для кэширования
2. Сохраняйте шаблоны на 1-24 часа
3. Это ускорит обработку и снизит нагрузку на API
